# Електронний журнал — специфікація

## 1. Коротко про тему

«Електронний журнал» — невеликий бекенд-застосунок для ведення обліку оцінок. Вчителі ставлять оцінки студентам за заняття зі своїх предметів, а студенти переглядають свої оцінки.

---

## 2. Критерії прийняття

- **Студент отримує лише свої оцінки:** за предметом (по заняттях) або за конкретне заняття.
- **Вчитель ставить оцінку**, лише якщо веде предмет цього заняття.
- **Оцінку можна поставити лише студенту** групи цього заняття.
- **Оцінка** — ціле число від 1 до 100; для пари `(студент, заняття)` існує не більше однієї оцінки.
- **Вчитель відкриває заняття** свого предмета і бачить студентів групи цього заняття.
- **Студент отримує свій середній бал** (середнє арифметичне всіх його оцінок).
- **Студент не ставить оцінки**; вчитель не бачитиме заняття чужих предметів і не ставить за них оцінки.
- Користувача ідентифікує заголовок `X-User-Id` (авторизації немає). Порушення правил повертають помилку, дані не змінюються.
- **Усі id** (заголовок `X-User-Id`, тіло, path, query) мають формат UUID; невалідний формат повертає `400` (для `X-User-Id` — `401`).

---

## 3. Структура та шари (Layered Architecture)

> **Правила:** застосунок розділено за принципом **Package-by-Layer** (`routes` → `services` → `repositories`). `routes` звертаються лише до `services`; до бази даних доступ мають лише `repositories`. Сервіс може викликати інші сервіси, але не чужі репозиторії.

| Шар              | Папка               | Відповідальність                                                                                                        |
| :--------------- | :------------------ | :---------------------------------------------------------------------------------------------------------------------- |
| **Routes**       | `src/routes/`       | HTTP-контролери Fastify. Приймають запити, зчитують `X-User-Id`, передають дані в сервісний шар та формують відповіді.  |
| **Services**     | `src/services/`     | Бізнес-логіка, валідація ролей (TEACHER/STUDENT), перевірка належності студентів до груп та обчислення середнього бала. |
| **Repositories** | `src/repositories/` | Прямий доступ до таблиць БД (`users`, `subjects`, `teacher_subjects`, `lessons`, `grades`).                             |

**Сервіси та залежності**:

| Сервіс           | Свої таблиці (через репозиторії) | Викликає сервіси                                 |
| :--------------- | :------------------------------- | :----------------------------------------------- |
| `UserService`    | `users`                          | —                                                |
| `SubjectService` | `subjects`, `teacher_subjects`   | —                                                |
| `LessonService`  | `lessons`                        | —                                                |
| `GradeService`   | `grades`                         | `UserService`, `SubjectService`, `LessonService` |

## 4. Дані та зв'язки

[_посилання на ERD_](./docs/diagrams/er/ER_Nodejs3.drawio.png)

### Схема бази даних

#### 1. Таблиця `groups`

Зберігає академічні групи студентів.

| Column | Type      | Keys / Constraints | Description                    |
| :----- | :-------- | :----------------- | :----------------------------- |
| `id`   | `UUID`    | **PK**             | Унікальний ідентифікатор групи |
| `name` | `VARCHAR` | `NOT NULL`         | Назва групи                    |

---

#### 2. Таблиця `users`

Зберігає профільну інформацію про всіх користувачів системи (студентів та викладачів).

| Column     | Type      | Keys / Constraints                       | Description                            |
| :--------- | :-------- | :--------------------------------------- | :------------------------------------- |
| `id`       | `UUID`    | **PK**                                   | Унікальний ідентифікатор користувача   |
| `name`     | `VARCHAR` | `NOT NULL`                               | ПІБ користувача                        |
| `role`     | `VARCHAR` | `CHECK (role IN ('STUDENT', 'TEACHER'))` | Роль у системі                         |
| `group_id` | `UUID`    | **FK** (`groups.id`), _Nullable_         | Група студента (`NULL` для викладачів) |

---

#### 3. Таблиця `subjects`

Каталог навчальних предметів.

| Column | Type      | Keys / Constraints | Description                       |
| :----- | :-------- | :----------------- | :-------------------------------- |
| `id`   | `UUID`    | **PK**             | Унікальний ідентифікатор предмета |
| `name` | `VARCHAR` | `NOT NULL`         | Назва предмета                    |

---

#### 4. Таблиця `teacher_subjects`

Зв'язок "багато-до-багато" між викладачами та предметами, які вони ведуть.

| Column       | Type   | Keys / Constraints         | Description            |
| :----------- | :----- | :------------------------- | :--------------------- |
| `teacher_id` | `UUID` | **PK, FK** (`users.id`)    | Посилання на викладача |
| `subject_id` | `UUID` | **PK, FK** (`subjects.id`) | Посилання на предмет   |

---

#### 5. Таблиця `lessons`

Зберігає інформацію про розклад та проведені заняття.

| Column       | Type        | Keys / Constraints                 | Description                     |
| :----------- | :---------- | :--------------------------------- | :------------------------------ |
| `id`         | `UUID`      | **PK**                             | Унікальний ідентифікатор уроку  |
| `group_id`   | `UUID`      | **FK** (`groups.id`), `NOT NULL`   | Група, для якої призначено урок |
| `subject_id` | `UUID`      | **FK** (`subjects.id`), `NOT NULL` | Предмет заняття                 |
| `date`       | `TIMESTAMP` | `NOT NULL`                         | Дата та час проведення          |

---

#### 6. Таблиця `grades`

Електронний журнал оцінок студентів.

| Column       | Type        | Keys / Constraints                | Description                     |
| :----------- | :---------- | :-------------------------------- | :------------------------------ |
| `id`         | `UUID`      | **PK**                            | Унікальний ідентифікатор оцінки |
| `student_id` | `UUID`      | **FK** (`users.id`), `NOT NULL`   | Студент, що отримав оцінку      |
| `lesson_id`  | `UUID`      | **FK** (`lessons.id`), `NOT NULL` | Урок, за який виставлено бал    |
| `score`      | `INTEGER`   | `CHECK (score BETWEEN 1 AND 100)` | Оцінка в діапазоні від 1 до 100 |
| `created_at` | `TIMESTAMP` | `DEFAULT NOW()`                   | Час створення запису            |

## Обмеження цілісності.

### У БД (CHECK/UNIQUE):

- role ∈ {STUDENT, TEACHER};
- group_id обов'язковий для студента й порожній для вчителя;
- оцінка 1–100;
  UNIQUE(student_id, lesson_id).

### У коді (service):

- у teacher_subjects лише користувачі з роллю TEACHER;
- оцінка ставиться лише користувачу з роллю STUDENT з групи заняття.

## 5. Ключові сценарії

### 1. Вчитель ставить оцінку

- **Ініціює:** вчитель (`POST` оцінки: заняття, студент, значення).
- **Кроки:** hook ідентифікує користувача (`UserService`) → route передає користувача й дані в `GradeService` → `LessonService` (предмет і група заняття) → `SubjectService` (чи веде вчитель предмет) → `UserService` (чи студент у групі заняття) → `GradeService` створює запис.
- **Зміна даних:** одна нова оцінка в таблиці `grades` (транзакція).
- **Приклад запиту:**
    ```sql
    INSERT INTO grades (id, student_id, lesson_id, score, created_at)
    VALUES ($1, $2, $3, $4, NOW())
    ON CONFLICT (student_id, lesson_id)
    DO NOTHING RETURNING score = EXCLUDED.score;
    ```
- **Очікувана відповідь:**
  **200 OK / 201 Created**
    ```json
    {
        "id": "uuid",
        "student_id": "uuid",
        "lesson_id": "uuid",
        "score": 95,
        "created_at": "2026-10-12T18:00:00.000Z"
    }
    ```
- **Помилки:**
    - `400` — значення поза межами 1–100 або `student_id` / `lesson_id` не UUID;
    - `401` — немає, невідомий або невалідний формат `X-User-Id`;
    - `403` — користувач не вчитель, не веде предмет, або студент не з цієї групи;
    - `404` — заняття чи студента не знайдено;
    - `409` — оцінка вже існує, дубль не створюється.
    - `503` — джерело даних недоступне (БД не відповідає), дані не змінюються.

### 2. Вчитель відкриває заняття і бачить студентів

- **Ініціює:** вчитель (`GET` заняття).
- **Кроки:** hook ідентифікує користувача → `GradeService` викликає: `LessonService` (заняття) → `SubjectService` (чи веде вчитель предмет) → `UserService` (студенти групи заняття).
- **Зміна даних:** немає (читання).
- **Приклад запиту:**
    ```sql
    SELECT
        l.id AS lesson_id,
        l.date,
        s.name AS subject_name,
        u.id AS student_id,
        u.name AS student_name
    FROM lessons l
    JOIN subjects s ON l.subject_id = s.id
    JOIN users u ON u.group_id = l.group_id AND u.role = 'STUDENT'
    WHERE l.id = $1;
    ```
- **Очікувана відповідь:**
  **200 OK**
    ```json
    {
        "lesson_id": "uuid",
        "date": "2026-10-12T10:00:00.000Z",
        "subject_name": "Математика",
        "students": [{ "student_id": "uuid", "student_name": "Іван Петренко" }]
    }
    ```
- **Помилки:**
    - `400` — `lessonId` не UUID;
    - `401` — немає, невідомий або невалідний формат `X-User-Id`;
    - `403` — не вчитель або не веде предмет;
    - `404` — заняття не знайдено.
    - `503` — джерело даних недоступне (БД не відповідає), дані не змінюються.

### 3. Студент переглядає свої оцінки за предметом або за конкретне заняття

- **Ініціює:** студент (`GET` оцінок з фільтром за предметом або заняттям).
- **Кроки:** hook ідентифікує користувача → `GradeService` вибирає оцінки з `student_id = поточний студент`; для предмета — через `LessonService` (заняття цього предмета), для заняття — оцінка за нього.
- **Зміна даних:** немає (читання); чужі оцінки недоступні.
- **Приклад запиту:**
    ```sql
    SELECT
        g.id AS grade_id,
        g.score,
        g.created_at,
        l.date AS lesson_date,
        s.name AS subject_name
    FROM grades g
    JOIN lessons l ON g.lesson_id = l.id
    JOIN subjects s ON l.subject_id = s.id
    WHERE g.student_id = $1
      AND ($2::UUID IS NULL OR l.subject_id = $2)
      AND ($3::UUID IS NULL OR g.lesson_id = $3);
    ```
- **Очікувана відповідь:**
  **200 OK / 201 Created**
    ```json
    [
        {
            "grade_id": "uuid",
            "score": 90,
            "created_at": "2026-10-12T18:00:00.000Z",
            "lesson_date": "2026-10-12T10:00:00.000Z",
            "subject_name": "Математика"
        }
    ]
    ```
- **Помилки:**
    - `400` — `subject_id` або `lesson_id` не UUID;
    - `401` — немає, невідомий або невалідний формат `X-User-Id`;
    - `403` — користувач не студент;
    - `404` — предмет чи заняття не знайдено.
    - `503` — джерело даних недоступне (БД не відповідає), дані не змінюються.

### 4. Середній бал студента

- **Ініціює:** студент (`GET` середнього бала).
- **Кроки:** hook ідентифікує користувача → `GradeService` обчислює середнє значення всіх оцінок поточного студента.
- **Зміна даних:** немає (значення обчислюється, не зберігається); якщо оцінок немає — результат `null`.
- **Приклад запиту:**
    ```sql
    SELECT AVG(score)::NUMERIC(5,2) AS average_score
    FROM grades
    WHERE student_id = $1;
    ```
- **Очікувана відповідь:**
  **200 OK**
    ```json
    {
        "average_score": 88.5
    }
    ```
- **Помилки:**
    - `401` — немає, невідомий або невалідний формат `X-User-Id`;
    - `403` — користувач не студент.
    - `503` — джерело даних недоступне (БД не відповідає), дані не змінюються.
