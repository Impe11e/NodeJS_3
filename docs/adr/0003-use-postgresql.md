# 0003. Вибір реляційної бази даних (PostgreSQL) замість документоорієнтованої (MongoDB)

- **Статус:** Прийнято

## Контекст та постановка проблеми

Для зберігання даних системи необхідно обрати тип системи управління базами даних. Вибір проходив між реляційною СУБД (PostgreSQL) та документоорієнтованою NoSQL СУБД (MongoDB).

## Розглянуті варіанти

1. **Документоорієнтована NoSQL БД (MongoDB):**
    - Збереження даних у вигляді гнучких JSON-подібних документів.
    - Відсутність суворих Foreign Keys та обмежень на рівні бази даних за замовчуванням.

2. **Реляційна SQL БД (PostgreSQL):**
    - Чітка таблична структура зі строгою схемою типів даних.
    - Вбудована підтримка Foreign Keys, унікальних індексів (`UNIQUE`), обмежень значень (`CHECK`) та ACID-транзакцій.

## Результат рішення

**Обрано варіант 2:** Реляційна база даних (PostgreSQL).

### Обґрунтування:

- **Гарантія цілісності даних:** Зовнішні ключі (`FOREIGN KEY`) унеможливлюють створення «сирітських» записів (наприклад, оцінки без існуючого студента чи предмета).
- **Відсутність дублювання:** Дані збережені у нормалізованому вигляді. Зміна назви предмета чи даних викладача відбувається в одному місці.
- **Зручність аналітики:** Розрахунок середнього бала чи відомостей успішності реалізується за допомогою стандартного SQL (`JOIN`, `GROUP BY`, `AVG`).

## Наслідки

### Позитивні:

- Надійність та цілісність даних на рівні самої бази даних.
- Відсутність аномалій оновлення.
- Нативна підтримка складних агрегаційних запитів.

### Негативні:

- **Потреба у міграціях:** Будь-яка зміна структури таблиць вимагає написання та виконання SQL-міграцій.
