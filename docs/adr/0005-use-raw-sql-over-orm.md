# ADR-0005. Використання чистого SQL замість ORM для роботи з базою даних

- **Статус:** Прийнято

## Контекст та постановка проблеми

Для проєкту «Електронний журнал» на базі Node.js (ESM), TypeScript, Fastify та PostgreSQL необхідний механізм взаємодії з реляційною базою даних. Додаток має чітку тришарову архітектуру (`routes` → `services` → `repositories`), де весь доступ до даних інкапсульований у репозиторіях. Постало питання вибору підходу до написання запитів: використання повноцінних ORM (наприклад, Prisma чи TypeORM) чи застосування нативного SQL через легкий драйвер (`pg`).

## Розглянуті варіанти

- **Варіант 1: Використання ORM ( Prisma / TypeORM )** — декларативне визначення моделей, автоматична генерація міграцій та типизація запитів на основі схеми.
- **Варіант 2: Чистий SQL через нативний драйвер PostgreSQL (`pg`)** — написання прямих SQL-запитів, повний контроль над синтаксисом, транзакціями та оптимізацією.

## Рішення та обґрунтування

**Обрано Варіант 2 (Чистий SQL через `pg`), тому що** бізнес-логіка проєкту вимагає використання специфічних та оптимізованих реляційних запитів (складні `JOIN`-и для збору розкладу зі списком студентів, агрегації для розрахунку середнього бала, конструкції типу `ON CONFLICT` для атомарного проставлення оцінок). Нативні SQL-запити вже повністю спроєктовані в специфікації (`spec.md`) і можуть бути перенесені в код репозиторіїв безпосередньо без перетворення у вигадливий синтаксис ORM-абстракцій. Це знижує поріг входження, виключає зайві залежності та генератори коду.

## Наслідки

- **Позитивні наслідки:**

    - Повний і абсолютний контроль над ефективністю та продуктивністю SQL-запитів.
    - Відсутність потреби вивчати специфічний DSL (domain-specific language) сторонніх ORM.
    - Пряме співпадіння логіки між специфікацією (`spec.md`) та кодом у шарі репозиторіїв.
    - Мінімальний розмір бандла та відсутність сторонніх важких залежностей.

- **Негативні наслідки та ризики:**

    - Необхідність самостійно слідкувати за мапінгом результатів запитів у TypeScript-інтерфейси.
    - Ручне написання міграцій та відсутність автоматичної генерації схем коду.
