# Пайплайн перевірок якості коду (Quality Checks)

Цей документ визначає регламент перевірок якості коду, синтаксису, стабільності та працездатності застосунку. Пайплайн ділиться на 3 рівні: від локальних перевірок при коміті до повного циклу валідації проєкту.

---

## 1. Рівень 1: Автоматичні перевірки при коміті (pre-commit)

Перевірки виконуються автоматично інструментом **Husky** із залученням **lint-staged**. Вони застосовуються виключно до файлів, доданих до Git Staging Area (`git add`), що забезпечує швидкість виконання.

### Мета
Запобігти потраплянню неформатованого коду та синтаксичних помилок у стаж репозиторію.

### Інструменти та CLI-команди

* **Форматування коду (Prettier):**
  ```bash
  npx prettier --check <staged_files>
  ```
  *(Автоматичне виправлення стилю перед перевіркою: `npx prettier --write <staged_files>`)*

* **Лінтинг та аналіз коду (ESLint):**
  ```bash
  npx eslint <staged_files>
  ```

---

## 2. Рівень 2: Автоматичні перевірки при публікації (pre-push)

Перевірки виконуються інструментом **Husky** безпосередньо перед відправкою комітів у віддалений репозиторій (`git push`).

### Мета
Запобігти завантаженню зламаного коду, помилок збірки або непрацездатного застосунку у віддалені гілки.

### Складові та CLI-команди

1. **Build Check (Перевірка компіляції / збірки):**
   ```bash
   npm run build
   ```

2. **Smoke Test (Перевірка базової працездатності):**
   ```bash
   npm run test:smoke
   ```
   Перевіряє успішний запуск застосунку, коректність ініціалізації модулів та підключення до бази даних, а також відгук ендпоінту `/version`.

---

## 3. Рівень 3: Повний цикл перевірок (Make-команди)

Призначений для локального запуску розробником перед створенням Pull Request, а також для виконання у CI/CD середовищах на чистій копії репозиторію (`git clone` + `npm install`).

### Мета
Комплексна валідація всього коду та бізнес-логіки проєкту згідно з Definition of Done.

### Команди Make

* **Запуск автотестів (`make test`):**
  Запускає повний тестовий suite (модульні та інтеграційні тести) за допомогою Jest.
  ```bash
  make test
  ```
  *Еквівалент CLI:*
  ```bash
  npm test
  ```

* **Повна перевірка проєкту (`make check`):**
  Послідовно виконує перевірку форматування, лінтера та весь комплекс автотестів. Повинна проходити з нульовим кодом помилки (`exit 0`).
  ```bash
  make check
  ```
  *Еквівалент CLI:*
  ```bash
  npx prettier --check . && npx eslint . && npm test
  ```

---

## Підсумок регламенту

| Етап | Тригер | Інструменти / Команди | Блокуюча дія |
| :--- | :--- | :--- | :--- |
| **pre-commit** | `git commit` | Prettier, ESLint (`lint-staged`) | Блокує створення коміту |
| **pre-push** | `git push` | Smoke-тест, Build check | Блокує відправку у Git |
| **Full Validation** | `make check` / CI | Prettier + ESLint + Jest | Блокує злиття PR (Merge) |
