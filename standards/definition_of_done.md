# Definition of Done

DoD застосовується до обсягу, заявленого у spec поточного завдання. Задача вважається виконаною, якщо вона перевірена на чистій копії репозиторію, відповідає [spec.md](./spec.md), а всі відхилення від специфікації зафіксовані в ADR.

## 1. Відповідність spec

- Реалізовано всі сценарії зі spec.md з описаними у специфікації кроками, змінами даних і кодами помилок.
- Ролі працюють за специфікацією: студент не ставить оцінки; вчитель працює лише з предметами, які веде, і зі студентами групи заняття.
- Користувача ідентифікує заголовок `X-User-Id`; без нього або з невідомим id повертається 401.
- Чітка слоїста архітектура: дотримано потік даних `routes → services → repositories`. Контролери не викликають репозиторії напряму, а репозиторії містять лише логіку доступу до даних.
- spec.md і README.md відповідають поточному коду: назви шарів, сервісів, таблиць, ендпоінтів і правил збігаються.

## 2. Тестування

- Кожен критерій прийняття зі spec.md покритий автотестом: успішний шлях і відповідні помилки (400, 401, 403, 404, 409).
- Окремо перевірено межові випадки: оцінки 1 і 100, значення поза діапазоном, повторна оцінка за те саме заняття, студент не з групи заняття, студент без оцінок (середній бал `null`).
- Усі тести проходять (`make test`), без пропущених (`skip`).

## 3. Якість коду

- Код відформатовано Prettier.
- ESLint проходить без помилок.
- У коді немає закоментованого коду та зайвих `console.log`.

## 4. Документація

- README.md актуальний: опис проєкту, стек, запуск і перевірки, структура репозиторію, посилання на документи.
- Ключові архітектурні рішення та відхилення від spec.md задокументовані в ADR за шаблоном MADR (контекст, варіанти, рішення, наслідки).
- DEFENSE.md (1 сторінка) заповнений за шаблоном, у ньому топ-3 розбіжності з посиланнями на коміти.
- spec.md не більше 1 сторінки, критерії прийняття зафіксовані окремим комітом.
- Наявні файли стандартів проєкту, і код їм відповідає.

## 5. Запуск і перевірка

- На чистій копії репозиторію (свіжий `git clone` + `npm install`) команда `make check` проходить повністю: форматування, лінтер і тести.
- Застосунок запускається за інструкцією з README.md без додаткових ручних кроків.
- Husky з lint-staged блокує коміти, що не проходять форматування та лінтер.
- Push блокується, якщо падає smoke-тест або збірка.
- `/version` повертає sha поточного коміту.

## 6. Git і репозиторій

- `.gitignore` чистий: у репозиторії немає `node_modules`, `.env`, логів та інших згенерованих або локальних файлів.
- Зміни здаються через pull request з описом, що саме зроблено і які критерії spec.md закрито.
- Кожен коміт це одна логічна зміна, spec закомічений окремо до коду, у PR немає випадкових або сторонніх змін.
